# 客户端行为（S4）

迁移前在真实 Buzz Desktop 确认团队成员与当前无活跃任务。选已有身份发带唯一验证标记的 DM，要求回复标记并运行只读 pwd；观察主时间线回复、工具 Activity 和结果。频道通过明确 @ 同一身份发验证请求，观察线程归属；非目标角色不得重复响应。

切换后重走上述路径，受限身份尝试对事先创建的无业务测试标记位置写入并应被拒绝（禁止拿真实业务文件做破坏探测），观察客户端错误/拒绝反馈。通过正常 Desktop 停止/启动验证身份 home 与会话恢复，观察无重复处理；用受控失败命令验证错误可见且后续请求仍能完成。每项记录 UI 证据，不以 API 读取结果替代 UI。
