# #64 契约：现行栈下席位不得跑「长静默」任务

状态：设计门已批（peng 经 Jenny 2026-10-09）。本文件是现行约束，不是抬参方案。权威时限在上游 buzz-acp / Desktop；buzz-team 源码面没有这些旋钮。

配套笔记：[`README.md`](README.md)。#38 idle 决策：[`docs/issue-38/IDLE-DECISION.md`](../issue-38/IDLE-DECISION.md)（本票引用，不修改）。

---

## 1. 不安全的任务

在现行栈上，**一轮进行中、中途有长时间无输出的长任务是不安全的**，前台与后台相同。

周衡观测包络（#64 正文 / L1；未在本仓实现）：

| 观测名 | 值 | 失败模式 |
|---|---|---|
| `idle_pool_sleep_seconds` | 900s | 整池 teardown，杀 agent 树 |
| `idle_timeout` | 1500s | 单工具无输出约 25 分钟后回收 agent |
| `max_turn` | 1800s | 单轮硬顶：杀并重启 agent，消息重新入队 → **可能静默重跑** |

另外两条已确认、且活动定义仍为 **未知** 的行为：

- idle 计时可以在本轮结束前开始；后台任务可以不重置 idle。
- teardown 杀树不完整，可能留下孤儿后代（#57 RUN3 的 grok **56637**）。

因此：不能假设「任务还在跑 = 池子还活着」，也不能假设「没有 teardown 日志 = 没有孤儿」。

---

## 2. 席位必须遵守的限制

跑长任务的席位（至少包括周衡）必须二选一：

1. **遵守现行包络**：任务设计须同时落在 900 / 1500 / 1800 之内，并假设静默**不**重置 idle。具体上：
   - 不要在席位内启动「单次十几分钟以上、中途长时间无输出」的工作（kairo 长 ref、长 `find`、长静默工具等待等）。
   - 不要依赖后台任务给 pool / idle / turn 续命。
   - 不要把「前台跑」当成逃生口：同一轮仍可能撞 1500 与 1800，且不能排除 900 的整池 teardown。
2. **等待另批的 per-seat 抬参**：仅当 Mac 只读已证实键可配，peng 给出三道数值（避免只抬一个），并（若抬 `idle_timeout`）先修订 `IDLE-DECISION.md`，再开独立活机窗。**本文件批准之前，禁止抬。**

禁止第三条默许路径：在席位里「先跑着看」，或把任务拆到 agent 进程外却不另开设计（选项 (3) 默认不采用）。

## 3. 静默重跑（开放门，不代选）

`max_turn` 硬顶会杀 agent 并把消息重新入队（周衡 9/30 08:18：`hard-cap timeout … requeueing for retry`）。同一工作可能被中断后悄悄再跑。

Knox P3-2：若将来抬 `max_turn` 仍为**有限值**，行为验收必须由 peng 择一，本契约不发明选择：

| 选项 | 含义 |
|---|---|
| 零重跑 | 观测窗口内 buzz-acp 日志无 `requeueing for retry` / 同等 hard-cap 重入队 |
| 可观测重跑 | 允许重跑，但必须有日志告警，且验收明确收集该行 |

在 peng 选定之前：席位任务须按「可能被静默重跑」来设计（幂等、可核对产物、不把启动成功当成完成）。禁止只写「无静默重跑」却保留有限硬顶。

## 4. 孤儿残留（本仓不根治）

配置抬参只能降低 teardown 概率。杀树不完整是上游行为。本仓不把「无孤儿」写成已修复。

观测方法（活机窗或事后只读；本契约 PR 不执行）：

- acp 日志 teardown 行之后，对照 memtrace 是否还有心跳
- teardown 后 `pgrep` 对照（目标席 grok / kairo / 脚本壳）
- 产物 mtime：有中间产物、无 `notes.jsonl` / 无 EXIT，视为中断或孤儿，不得算交付

56637 是阳性实例，不是唯一形态。
