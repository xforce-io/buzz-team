## 2. 问题

Mac 休眠或清醒漏触发后，`scheduled_workflow_fires` 没有行，也没有任何「错过」记录。Hogan / Scout 只能人工对 `pmset`。09-30 17:00–17:30 缺 4 次，全部落在 L1 休眠区间；同日上午醒着 6/6 正常。2026-10-23 只读补核仍是这 4 行缺失；live `pmset` 已滚到约 10-16，无法再现场证明 09-30。`buzz-health` 仍只做 #58，对账不存在。

机制见 [HOW.md](HOW.md)：relay 窗口 60 秒、不补跑。本票不对账之外做补救。

## 3. 目标与非目标

目标（本轮）：

- Mac 醒来后跑一次只读检查，列出对账窗内每一次应触发而未触发：定义 id、计划时间（CST）、覆盖它的休眠区间（若有）、分类标签。
- 用冻结的 09-30 17:00–17:30 回放，正好 4 行，标签均为「休眠期间」。
- 同一套检查能区分：休眠漏 = 「未知（休眠）」；醒着漏 = 「异常（醒着漏触发）」；`pmset` 已滚动 = 「未知（pmset 已滚动）」。
- 游标持久推进到 `now - 2min`，睡眠数小时后一次跑完缺口；晚到 grace 内的 fire 不误报；时钟回拨本轮跳过、游标不后退。

非目标：

- 修改上游 block/buzz（60 秒窗、补跑、tick 游标化）。
- 自动 / 人工补跑策略、席位私钥 `workflows trigger`、向频道发提醒（S3）。
- 元宝 relay；#62 残留清理；是否允许 Mac 休眠。
- 把 workflow DB 或 `pmset` 读进 `buzz-team doctor`。
- 改 `bin/buzz-health` 的 #58 退出契约（不写文件、不连 relay、不因本票 fail）。
- 重抓 09-30 live `pmset`；重拉 Desktop / ACP；向生产库写入（游标文件除外，且只写实例本地状态文件）。
- 修 colima 双对时源（10/06 根因，另票）。

## 4. Stories

### S1. 醒来后能看到漏掉的触发

对象：本地 community `14a17e2d-…` 上 8 条 enabled+active 的 schedule 定义。

操作者 Hogan：Mac 醒来后跑 sibling 只读检查（实现批准后的脚本；本 PR 只定契约）。输出列出对账窗内每条漏触发：定义 id、名称、owner 席位、cron、计划时间 CST、分类、覆盖休眠区间。不必再手工对 `pmset`。

定量：09-30 17:00–17:30 冻结回放 → 4 行，均标「休眠期间」，区间与 [HOW.md](HOW.md) 事实表一致。同日 08:45–09:30 回放 → 异常 0。

游标：若已有「已对账到」，一次跑覆盖休眠缺口到 `now-grace`。若无游标文件，**fail fast**，要求 `--since`（不静默扫全历史、不发明默认回溯天数）。

### S2. 区分「休眠」与「醒着漏触发」

同一检查、同一套标签，供 Scout 写产品日志，口径对齐 #62「Mac 休眠 = 未知」：

| 条件 | 标签 | 产品含义 |
|---|---|---|
| 有 fire 行 | 正常 | 不进漏触发列表 |
| 无 fire，计划时刻落在 [Sleep, 下一次完整 Wake)，或完整 Wake 后 60 秒内 | 未知（休眠）；S1 展示「休眠期间」 | 预期可能丢，不是实例故障 |
| 无 fire，当时醒着 | 异常（醒着漏触发） | 要看见；10/06 `7d90ca75` 09:30 属此类 |
| 无 fire，计划时刻早于本机 `pmset` 最早记录 | 未知（pmset 已滚动） | 不能判异常 |
| cron 0.16 下当日不应触发（如 apply 前周五 `f5cc62c0`） | 不列入应触发 | 不是漏 |

DarkWake 不算醒来。定量：醒着夹具缺 1 条 fire → 异常 1；休眠 4 条 0 条被标异常。
